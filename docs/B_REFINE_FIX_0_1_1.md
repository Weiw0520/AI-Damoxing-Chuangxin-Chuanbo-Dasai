# 追问流程 0.1.1 加固与失败案例恢复

本次加固基于 B 于2026-11-20提交的真实结果包。普通案例的精简、连续追问、依据说明、保存与接口导出完成；缺票价案例生成成功，但强制填写30元追问返回502，具体模型阶段或结构原因未随旧接口保存，不能断言根因。

## 加固内容

1. 服务端 `pending_` 资料缺口提示不再作为可编辑正文发送给改写模型，但仍保留在规范化原请求及输入摘要中。缺口由 `mandatory_missing_fields` 传达并由服务端统一呈现。
2. 模型若回显标准票价缺口提示，仅在文字确为标准缺口通知、没有引文断言且当前确实缺少票价时交还服务端渲染。普通事实、伪造引文和任意使用保留编号的段落仍严格拒绝；不吞掉不安全事实，也不以失败回退伪装改写成功。
3. 保留原来的 `AI_REFINEMENT_FAILED` 错误码和通用消息，增加经过白名单分类的 `diagnostic_code`；HTTP错误仅附受控阶段与状态码，不返回提供方原始响应、凭据或任意异常文本。
4. 提示词文本与版本不变。新增审计字段 `ai_meta.pipeline_version=refine-core/0.1.1`，用于区分流程实现版本，不把代码调整伪装成提示词迭代。

已复现“模型回显服务端标准提示导致旧版结构校验失败”的兼容性问题并加固；这不能证明它就是本次历史502的实际原因。实际原因和改进效果仍以本机补测结果为准。
