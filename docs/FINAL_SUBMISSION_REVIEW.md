## 修复依据与行为

修改源码前，先读取原报告与 `race.cjs`、`save-switch-race.cjs`，在新库/新浏览器中再次复现：R1回执后编辑器关闭、人工新句消失；R2旧稿保存回执让新稿dirty消失，文字没有进入新稿数据库。新增12项状态层测试在旧实现中10失败、2通过。

每个保存/追问请求现在绑定草稿ID、单调请求ID、页面会话、版本、提交正文/历史快照和逐段编辑修订号。成功、catch、finally均检查归属；切稿、重开同稿、新建会建立新会话，旧回执不能更改新页面、错误或新请求的busy状态。乱序打开草稿的GET回执也有导航请求ID保护。

- **保存**：只把提交时的文本确认为已保存基线；提交之后输入的内容继续作为未保存编辑。不会从回执到达时的全局edits中取字并误认已保存。
- **追问**：正常应用服务端正文/版本/依据/历史，同时将提交后的人工编辑叠回页面，保持编辑器可见及dirty；即使用户先输入再改回提交时的同一字符串，编辑修订号也能识别并保留人工意图。
- **结构冲突**：若AI删除/换号了后来又被人工编辑的段落，将完整人工文字放入存续首段末尾的可见“结构冲突”区，提示整理后保存。不会放进不可见的旧段ID，也不偷偷新增服务器不接受的段落。恢复区仍是未保存人工文字，实际保存后由现有后端标待复核。
- **失败/重复操作**：失败保留输入及当前编辑；同一页面保存忙时避免重复发送；切到另一稿后仍可编辑、保存和追问，没有通过禁用全部编辑或切稿绕过问题。

## 3. 阻塞问题与非阻塞限制

### 必须修复：R1 追问成功回执清掉请求发出后的人工编辑

位置：`frontend/src/stores/draft.js:706-735`，尤其`:720`整体替换segments、`:728`无条件清空edits并退出编辑模式。

实际浏览器复现：

1. 打开普通测试草稿v4，右栏处于编辑状态，提交追问。
2. 模型响应暂缓，发送按钮已禁用，但正文textarea仍可编辑。
3. 输入“追问提交之后才输入的新句，请保留这条尚未保存的人工编辑。”，确认页面中可见。
4. 放行真实接入流程的测试模型200回执，草稿升至v5。
5. 新句从页面消失，编辑模式关闭；响应、数据库、历史均没有该新句。

这是**请求快照之后的人工编辑丢失**，不是模型合理改写了提交内容。回执只核对draftId，无法识别同稿后续编辑；切出再切回同ID也存在同类静态风险，后者未另做完整浏览器复现。证据：`race.json`、`race-lost-edit.png`。

最小修复方向：按请求身份、页面会话和编辑修订号应用回执；只清理本次提交时的编辑快照，保留或显式处理之后的编辑。可保持A布局和原有功能。需新增浏览器回归，不能只加后端测试。

### 必须修复：R2 保存回执跨稿更新状态，造成“已保存”的假象

位置：`frontend/src/stores/draft.js:883-949`。这段保存逻辑沿用A原版，**不是PR #6新增修改**。请求发出后，成功分支使用的是当前的 `state.result/state.edits/state.draftId`，未绑定请求所属草稿和正文快照。

实际浏览器复现：

1. 编辑缺票价稿，点击保存；后端实际已保存200，仅延迟浏览器接收回执。
2. 切换到普通稿，按页面确认放弃原页面未保存状态。
3. 在普通稿输入另一新句：“切换到普通稿之后才输入的修改，尚未对普通稿执行保存。”
4. 放行缺票价稿的旧保存回执。
5. 普通稿仍显示新句，却显示“已保存v6”，未保存警告消失；普通稿数据库没有新句，刷新后新句消失。

数据库没有被跨稿覆盖；**页面把另一稿的保存成功用于当前稿，清掉了当前编辑的待保存状态**，用户无法可靠判断是否已保存。证据：`save-switch-race.json`、`save-switch-false-saved.png`。此次故障仅延迟HTTP回执，不伪造后端200，也不调用模型。

最小修复方向：保存时捕获draftId、提交正文和编辑修订号；跨稿回执只更新列表，不更新当前稿正文/历史/版本；同稿的新编辑保持dirty。需同时回归同稿保存期间继续输入、跨稿保存、失败重试。
