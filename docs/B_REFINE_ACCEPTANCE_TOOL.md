# 追问接口真实验收收集工具

工具为 `scripts/run_b_refine_acceptance.py`，使用Python标准库，不新增依赖。后端 `backend.a_ai_main:app` 应已在本机8000端口运行并配置模型；工具只访问本机后端，不需要输入模型Key，不采集环境变量、认证头、Git配置或源码diff。

从项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run_b_refine_acceptance.py
```

会新建普通、缺票价两份统一材料草稿，执行四次追问：精简、连续修改、依据说明和要求编造票价。随后人工修改一个段落（由工具通过人工保存接口提交）、回读、导出。仅操作本次新建的草稿，不覆盖原有验收草稿。真实模型仍会由后端实际调用，不是回放；非real/live响应会被拒绝作为真实验收。

自动记录每条请求的载荷、完整JSON响应、HTTP状态、耗时、草稿编号、版本、模型元数据、代码HEAD/分支/工作区状态及关键源码哈希。JSON是UTF-8排版整理，不是HAR。`*.api-export-content.txt` 是服务端响应写出的文本，不能当作真实浏览器下载文件。

结果包固定显示为项目下 `data/b-refine-acceptance/B_REFINE_ACCEPTANCE_LATEST.zip`，每次运行的原始目录另外按时间保存。失败项也保留响应，不填造通过结论。data目录按项目现有规则忽略，不会自动成为提交内容。

脚本只自动检查版本、引文结构、已知票价缺口和持久化等确定性事项。文案是否满足改写要求、引文是否支持全部语义、网页呈现和实际浏览器下载仍需人工复验；不能把“自动检查完成”直接当作全部验收通过。

## 同库重启读取

第一轮完成后，由操作者在后端终端Ctrl+C，并保留原来的 `DRAFT_DB_PATH` 和模型配置，重新启动相同AI入口。随后从项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run_b_refine_acceptance.py --verify-restart
```

读取当前记录中已保存的测试草稿（包括补测草稿），与保存时的完整快照比较并更新结果包。脚本不能独立证明操作者确实重启过进程，因此记录中明确保留这一步的人工操作属性。端口非8000时，两次命令均需加同一个 `--base http://127.0.0.1:端口`。

## 版本与证据边界

若追问代码尚未提交，HEAD仍可能是旧验收提交。工具会明确保留工作区状态和源码哈希，不能把旧HEAD单独标成已经包含追问功能的新测试版本。记录复核后再整理成正式的 `B_REFINE_REAL_ACCEPTANCE.md`，旧验收记录保持原样。

当前实现没有自动操纵浏览器、创建Git提交、推送、合并PR或修改模型配置。请把生成的结果包交给审阅者核对，并补充网页截图与实际TXT文件。

## 仅补测缺票价：0.1.3

当旧结果已200但正文退化为占位句，不要继续在该占位稿上测试。安装0.1.3、保留原数据库和模型配置启动后，从同一项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run_b_refine_acceptance.py --recheck-price
```

读取上次结果记录，只新建一份同材料缺票价草稿，执行一次强制填30元追问，然后保存、回读、服务端导出；不重跑普通案例，不覆盖旧稿、旧502或旧200。记录键名missing_price_recheck_1等，`current_price_case`指向本次补测。新资料生成和追问仍会使用真实模型，Key仅由后端读取。

新增正文保留门槛：地点“山东、潍坊、杨家埠”和类别“民间版画”、钩描/刻版/印刷三道工序须出现在有引文的verified段落内。仅无30元和有待核验提示还不够；若正文全部占位化，即使200也判失败，并停止后续保存。这是统一案例的确定性内容门槛，不替代完整语义和网页复核。

旧的`--resume-failed`只适合尚未改稿的原缺票价502；已完成但内容降级的旧稿改用`--recheck-price`。所有新结果继续写入data/b-refine-acceptance/B_REFINE_ACCEPTANCE_LATEST.zip。
