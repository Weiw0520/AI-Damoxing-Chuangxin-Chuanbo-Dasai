# B真实网页追问、保存与下载验收

本工具补充接口验收后的浏览器证据，不改变前端或AI接口。它操作已有普通、新缺票价两份测试草稿，使用已运行后端的模型配置，不接收或读取AI_API_KEY，不收集环境变量、认证头或其他草稿详情。

## 运行条件

- 已安装本项目追问0.1.3和接口验收工具，`data/b-refine-acceptance/latest-run.json` 指向刚完成的记录，其中含current_price_case与普通案例。
- 后端 `backend.a_ai_main:app` 在本机8000运行，前端真实后端网络模式在5173运行。保持原DRAFT_DB_PATH和模型配置。
- Windows安装了Edge或Chrome。工具优先启动Edge，使用隔离浏览器上下文，不复用个人浏览记录或登录状态，不安装浏览器。
- 网页验收依赖单独列在scripts/requirements-web-acceptance.txt，属于可选验收工具，不改变backend/requirements.txt。CMD启动器首次缺少Playwright时安装该依赖，之后直接运行。

从项目根目录运行：

```powershell
.\scripts\run_b_refine_web_acceptance.cmd
```

所有页面操作由脚本进行。运行期间保持前后端终端打开，避免同时修改同一份验收草稿。它只发送一次AI追问，没有自动模型重试；不重跑两份首次生成。

## 实际执行范围

1. 先读取新票价草稿，并与接口验收v3快照完整比较；如果已被改动，停止而非重复覆盖或重复调用模型。
2. 通过页面左侧真实对话按钮打开草稿，在底部会话框要求保留正文、补齐第二段类别和工序引文，并重新核验。
3. 保存该次真实refine请求、响应、状态和浏览器请求耗时；拒绝mock、空正文、不完整引文、资料外30元/免费断言和丢失票价待核验。
4. 在核验报告中打开P2依据抽屉，检查来源编号、类别与工序原文并截图；再截图票价待核验抽屉。若第二段仍写“民间版画”，其自身quotes必须包含类别原文，不能借前一段引文冒充。
5. 在右栏编辑第一段，通过网页保存按钮追加一句出发前核实门票的个人表述。检查PUT回执只改P1并增加一版，刷新重开后确认新句、人工修改后待复核和清空旧引用。
6. 从右栏下载文案正文，捕获真实浏览器下载及对应export 200，保留原始TXT字节。A下载器会加UTF-8 BOM，解码去BOM后必须与服务端content逐字一致，文件名、草稿编号和版本也一致；接口失败后的本地兜底不算成功。
7. 打开普通案例，下载其实际TXT并做相同比较，不再调用普通案例模型或修改其内容。随后返回新票价草稿供查看。

截图只截取当前草稿卡片、依据抽屉或文件栏，不保存其他对话列表、个人浏览器界面或后端终端。

## 最后一次同库重启

网页保存后版本已增加，不能再拿旧接口v3快照比较。工具保存了新的网页最终快照，完成浏览器操作后会在终端暂停：

1. 在原后端终端Ctrl+C，保持原DRAFT_DB_PATH和模型配置，重新启动相同AI入口。
2. 回到工具终端按回车。脚本只GET回读两份最新网页快照并比较，不再次调用模型。

若输入s跳过或操作中断，网页已有结果仍保留。后续同库重启后可从项目根目录补执行：

```powershell
.\scripts\run_b_refine_web_acceptance.cmd --verify-restart
```

重启动作为操作者执行，脚本只能证明回读数据一致，不能独立证明进程确实重启。网页失败或缺少两份最终快照时，不会把重启标为通过。

结果包：`data/b-refine-web-acceptance/B_REFINE_WEB_ACCEPTANCE_LATEST.zip`。按运行时间保留独立原始目录；含请求/完整JSON响应、状态和耗时、草稿号/版本、模型元数据、代码与工具摘要、截图、实际下载TXT及文件校验、最新快照和报告。它与旧B_REFINE_ACCEPTANCE_LATEST.zip分开保存。

遇到模型错误、控件变化、引用未补齐或版本冲突会停止后续写入并保留已完成证据。若模型追问已保存而后续步骤失败，不自动恢复或覆盖旧稿，也不重新发请求假装成功。报告中的语义仍待审阅，不能把自动规则通过当作所有表达都正确。

本工具的8项离线测试覆盖：段内类别引文缺失、mock/伪引文/编票价拒绝、真实TXT去BOM精确比较、重启失败不保留旧passed状态，以及完整JSON响应体读取不创建多余关闭监听、缺失网络耗时不伪造为0。首版工具已由B在Windows Edge 151.0.4129.101实际运行，完整结果见B_REFINE_REAL_ACCEPTANCE.md及acceptance/b-refine-web/20261120。当前云端仍无法启动浏览器；工具0.1.1收尾修复只有离线验证，没有重复调用真实模型。

## 0.1.1：浏览器退出时的Target closed日志

收到的日志为 `Response.finished.<locals>.on_finished` 的 `Task exception was never retrieved / Target closed`。当前Playwright 1.62.0的finished方法为每次调用创建target-close监听任务，正常响应先完成时该任务仍存活，浏览器退出后可能留下未读取异常。已用同版本实际内部方法和模拟完成/关闭future复现此日志；未运行模型、浏览器或改动草稿。

工具0.1.1不再调用finished，直接用json读取完整响应体，然后读取网络计时；拿不到完整responseEnd则记录null而非0。没有全局吞掉Playwright异常，也没有把失败改成通过。现有8项测试通过。此工具版本与AI核心refine-core/0.1.3分别记录，未修改AI模块。

仅凭这类收尾日志不能判定网页流程失败，也不能判定通过。先提交已经生成的B_REFINE_WEB_ACCEPTANCE_LATEST.zip，核对manifest状态、最终JSON、截图、实际下载文件和重启结果。不要为了这些日志重复发送模型请求。若原报告完整，保留原版本证据；修复版用于后续运行和代码交付。
